# 零基础求解器入门指南

> 配套原文：*A Survey for Solving Mixed Integer Programming via Machine Learning*  
> 配套译文：[《通过机器学习求解混合整数规划：综述》](/blog/mip-survey-translation/)  
> 适合读者：没有运筹学、最优化或机器学习基础，第一次接触“求解器”的人。

## 0. 先用一句话看懂整篇综述

**这篇综述研究的不是“让神经网络凭空猜答案”，而是“让机器学习帮助传统求解器更快地做关键选择”。**

传统求解器像一个极其耐心的搜索者：它会尝试各种方案、排除不可能的方案，并在条件允许时证明答案最优。机器学习像一个从历史经验中学习的小助手：它可以建议“下一步先试哪个变量”“先搜索哪个分支”“加入哪条割”“选哪个启发式算法”。

整篇论文可以压缩成下面这张图：

```text
现实问题
  ↓ 建模
混合整数规划（MIP）
  ↓ 交给求解器
┌──────────────────────────────┐
│ 精确路线：分支定界 + 割平面    │ → 最终可证明最优，但可能很慢
│ 近似路线：LNS、可行性泵等      │ → 更快找好解，但通常不保证最优
│ 配置路线：预测并选择已有方法   │ → 让已有求解器更好用
└──────────────────────────────┘
  ↑ 在这些环节中，机器学习可以提供建议
```

你不需要先懂神经网络，才能理解这篇综述。**先理解求解器在做什么，再看机器学习能插入哪里，才是正确顺序。**

## 1. “求解器”到底在解什么？

### 1.1 从工厂排产说起

假设一家工厂生产两种产品：

- 产品 A：每件利润 3 元；
- 产品 B：每件利润 2 元；
- 两种产品共用两台设备，设备工时有限；
- 产品只能按整件生产，不能生产 1.37 件。

你要决定 A、B 各生产多少件，使总利润最大。

这就是优化问题：在限制条件下，作出最好的决策。

“求解器”就是接收这种数学问题并计算答案的软件。常见的名字有 Gurobi、CPLEX、SCIP、HiGHS。它们不是某一种单一算法，而是许多算法的组合系统。

### 1.2 四个最基本的名词

| 名词 | 在工厂例子中的含义 |
|---|---|
| **决策变量** | 你可以决定的量，例如生产几件 A、几件 B |
| **约束** | 不能违反的规则，例如设备工时不能超过上限 |
| **目标函数** | 想最大化或最小化的东西，例如利润或成本 |
| **可行解** | 满足全部约束的一组变量取值，不一定最好 |

再补两个经常被混淆的词：

- **最优解**：在所有可行解中，目标值最好的解。
- **问题实例**：把具体数字全部给定后的一个问题。例如“这台机器有 8 小时、那件产品有 2 元利润”就是一个具体实例；换成别的数字，就是另一个实例。

### 1.3 为什么叫“混合整数规划”？

“整数”指部分变量必须取整数，例如：

- 生产多少件产品；
- 派出多少辆车；
- 是否建设一座仓库：0 表示不建，1 表示建；
- 某台机器是否开启：0 或 1。

“混合”指模型里还可以有连续变量，例如：

- 使用多少升原料；
- 输送多少千瓦电力；
- 延迟多少小时。

所以：

- 只有连续变量，通常是线性规划（LP）或非线性规划；
- 所有变量都是整数，是整数规划（IP）；
- 既有整数变量又有连续变量，是混合整数规划（MIP）；
- 目标与约束均为线性式子时，是混合整数线性规划（MILP）。

**这篇综述只讨论 MILP，并在后文直接把它简称为 MIP。**

### 1.4 “规划”不等于做计划

这里的 programming 是历史沿用的数学术语，不是“写计算机程序”。混合整数规划是一种数学模型；用 Python 调用求解器，才涉及通常意义上的编程。

## 2. 看懂论文公式的最低要求

论文式（1）写成：

$$
\begin{aligned}
\min \quad & c^T x \\
\text{s.t.} \quad & Ax \geq b,\quad x\in\mathbb{R}^n,\\
& x_j\in\mathbb{Z},\quad \forall j\in I .
\end{aligned}
$$

逐块翻译成人话：

| 符号 | 人话 |
|---|---|
| $\min$ | 最小化；若要求最大利润，就改成 $\max$，或最小化利润的相反数 |
| $x$ | 所有决策变量排成的一列 |
| $c$ | 每个变量在目标中的成本系数 |
| $c^Tx$ | 把“变量取值 × 对应成本”全部加起来 |
| s.t. | subject to，即“满足以下约束” |
| $Ax\geq b$ | 所有线性资源、产能和需求约束的紧凑写法 |
| $x\in\mathbb R^n$ | 一共有 $n$ 个变量，暂时允许它们取实数 |
| $x_j\in\mathbb Z$ | 第 $j$ 个变量必须是整数 |
| $\forall j\in I$ | 对集合 $I$ 中的每个变量都施加整数要求 |

你暂时不需要会矩阵运算。只要记住：**$x$ 是待决定的答案，$c$、$A$、$b$ 是题目给定的数据。**

### 一个完整的小例子

设 $x$ 为产品 A 的数量，$y$ 为产品 B 的数量：

$$
\begin{aligned}
\max\quad &3x+2y &&\text{（利润最大）}\\
\text{s.t.}\quad &2x+y\leq4 &&\text{（设备 1 工时限制）}\\
&x+2y\leq4 &&\text{（设备 2 工时限制）}\\
&x,y\geq0,\\
&x,y\in\mathbb Z &&\text{（必须整件生产）}.
\end{aligned}
$$

它的整数最优解是：

$$x=2,\quad y=0,\quad \text{利润}=6.$$

后面会用同一个例子解释分支定界。

## 3. 最难的部分不是算数，而是“整数”

如果取消整数要求，允许 $x,y$ 取小数，就得到原问题的 **LP 松弛**。

上述例子的 LP 松弛最优解为：

$$x=\frac43,\quad y=\frac43,\quad \text{利润}=\frac{20}{3}\approx6.67.$$

但工厂不能生产 $4/3$ 件产品，所以它不是原问题的可行解。

### 3.1 为什么故意把问题放松？

因为连续 LP 通常容易求解，而整数解很难找。更重要的是，LP 松弛能提供一个“理论边界”。

本例是最大化问题：

- 放松限制后，可选择方案更多；
- 所以松弛后的最好利润不可能比原整数问题更差；
- LP 最优值 6.67 因而是整数最优值的**上界**。

既然整数利润一定是整数或至少是离散的，你甚至可以直觉地知道，真实答案不可能达到 6.67。

对于论文采用的最小化问题，方向相反：

- LP 松弛给出的是**下界**；
- 任意可行整数解给出的是**上界**。

请记住下面这张表：

| 问题方向 | LP 松弛给出的界 | 已知可行解给出的界 |
|---|---|---|
| 最小化 | 下界：最优成本不可能更低 | 上界：最优成本不会高于当前可行解 |
| 最大化 | 上界：最优收益不可能更高 | 下界：最优收益不会低于当前可行解 |

### 3.2 可行解、当前最好解与最优性证明不是一回事

假设你已经找到成本为 100 的可行解，LP 和搜索树给出的全局下界为 96：

- 你手上有一个能用的方案，成本 100；
- 你知道真正最优成本不可能低于 96；
- 因此最优成本位于 $[96,100]$；
- 目前还不能证明 100 就是最优。

这里：

- 100 对应的最佳已知可行解叫**当前最好解**（incumbent）；
- 96 叫**对偶界**或全局下界；
- 二者差距反映还剩多少不确定性，常用 **gap（间隙）**表示。

所以“求解器输出了一个答案”不代表“求解器已经证明它最优”。达到时间限制时，求解器经常返回当前最好解和最优性间隙。

## 4. 分支定界：把难题拆开，再用界排除搜索区域

分支定界（branch and bound，B&B）是综述第 2 节的核心。

它做两件事：

1. **分支（branch）**：把一个大问题拆成几个更小的问题；
2. **定界（bound）**：计算每个小问题最多可能有多好，排除没有希望的区域。

### 4.1 用工厂例子走一遍

原问题的 LP 松弛最优解是 $x=y=4/3$，其中 $x$ 不是整数。

针对 $x$ 分支，构造两个子问题：

```text
根节点：原问题
LP 松弛：x = 4/3，y = 4/3，利润上界 = 6.67
│
├─ 左子问题：增加约束 x ≤ 1
│  LP 松弛最优值 = 6
│
└─ 右子问题：增加约束 x ≥ 2
   LP 松弛最优解 = (2, 0)，利润 = 6，恰好是整数可行解
```

这两个分支覆盖了原问题的全部整数解：任何整数 $x$ 要么不超过 1，要么至少为 2，没有遗漏。

假设右子问题先被搜索，就得到当前最好利润 6。左子问题的 LP 上界也是 6，说明它内部任何整数解都不可能优于 6，因此无需继续展开。这就是**剪枝**。

最终：

- 所有未搜索区域要么已经搜索，要么被证明不可能更好；
- 当前最好解 $(2,0)$ 就是最优解；
- 求解器不只是“找到了”它，还“证明了”它。

### 4.2 树为什么可能爆炸？

每次分支都可能增加两个节点。若很多节点都不能被剪枝，节点数会快速增长。

这解释了综述为什么重视分支决策：

- 选择不同的分数变量分支，树的大小可能差很多；
- 先搜索哪个节点，会影响多快找到好解；
- 好的当前最好解越早出现，后面越容易剪枝；
- 一次糟糕选择可能让大量计算浪费在无意义区域。

### 4.3 三个最适合机器学习插入的位置

| 决策 | 传统求解器在问什么 | 机器学习可以学什么 |
|---|---|---|
| **分支变量选择**（第 2.1 节） | 哪个分数变量最值得拿来分支？ | 给候选变量打分，选择可能让搜索树更小的变量 |
| **节点选择**（第 2.2 节） | 下一步搜索哪个待处理节点？ | 优先选择更可能含好解或有助于证明最优的节点 |
| **割平面选择**（第 2.3 节） | 大量候选割中，加入哪些最有效？ | 给候选割打分，减少无效割带来的模型膨胀 |

这三件事对应综述表 1 的大部分工作。

## 5. 割平面：不切掉整数答案，只削掉多余的分数区域

LP 松弛的可行区域通常比整数可行区域“宽松”。割平面方法希望加入新的线性约束，让这个区域更贴近真正的整数问题。

一条合法的割必须满足：

- 不切掉任何原问题的整数可行解；
- 最好能切掉当前没有意义的分数区域，尤其是当前 LP 的分数最优解。

直观地说：

```text
原来的 LP 区域很大，当前最优顶点是小数解
              ↓ 加一条合法的割
小数顶点被排除，所有整数可行解仍保留
              ↓ 再解 LP
新的 LP 界更紧，分支定界更容易剪枝
```

**分支定界 + 割平面 = 分支切割（branch-and-cut）**，这是现代 MIP 求解器的核心框架之一。

机器学习在这里主要负责“选割”，而不是随意生成一条看似有用的约束。若割的有效性没有保证，就可能切掉真正的最优解。

## 6. 启发式算法：先拿到好答案，不执着于证明

精确算法最坏情况下可能需要极长时间。工业上经常只需要“在规定时间内足够好”，于是使用启发式算法。

### 6.1 大邻域搜索（LNS）

把当前可行解想成一套已经排好的生产计划。LNS 的做法是：

1. 固定大部分决策；
2. 放开其中一部分变量；
3. 在这个较大的“邻域”里重新优化；
4. 如果找到更好的完整方案，就接受它；
5. 重复，直到时间用完。

它像装修：不是每次都把整栋楼推倒重建，而是保留大部分结构，挑一层或几间房重新设计。

两个关键问题是：

- 初始方案从哪里来？
- 每次放开哪些变量、放开多少？

机器学习可以预测初始解、选择邻域，或者动态调整邻域大小。这就是综述第 3.1 节的内容。

### 6.2 可行性泵（FP）

MIP 求解中有两种要求经常冲突：

- LP 解满足线性约束，但可能不是整数；
- 直接取整后得到整数，但可能违反线性约束。

可行性泵在两者之间反复“弹跳”：

```text
解 LP → 取整 → 投影回 LP 可行区域 → 再取整 → ……
```

如果陷入循环，就随机扰动。目标是尽快找到任何一个可行解，而不是直接追求最优。

机器学习可以学习“下一步取哪个点”，不再机械地选择欧氏距离最近的点。这就是第 3.2 节的智能可行性泵。

### 6.3 预测与选择

这条路线更直接：保留成熟求解器，让机器学习做外围辅助，例如：

- 预测哪些约束可能冗余；
- 预测一个好的初始可行解；
- 预测变量可能的取值，把困难部分留给精确搜索；
- 根据实例特征选择合适的启发式算法；
- 预测何时可以提前停止。

**热启动（warm start）**就是先把一个已有好解交给求解器，让它不从零开始。

## 7. 机器学习部分，只需要先懂三种学习方式

### 7.1 监督学习：看标准答案

训练数据形如：

```text
输入：当前节点、变量和约束的特征
标签：专家当时选择了哪个变量，或哪个变量最终表现最好
```

模型学会后，在新实例中预测标签。

难点是“标准答案”未必真的最优。例如强分支在一两步内表现好，不一定让整棵树最小。

### 7.2 模仿学习：模仿专家的动作

模仿学习与监督学习关系很近，但强调 sequential decision，即连续决策。

综述中的典型例子是模仿**强分支**：

1. 强分支尝试多个候选变量，并计算各自分支后的效果；
2. 它质量较好，但每次都试算，成本很高；
3. 收集它的选择作为专家示范；
4. 训练一个便宜模型，在新节点直接给出类似选择。

可以把它理解为：让反应快的学生学习一位计算很慢的老师。

### 7.3 强化学习：通过长期结果学习

强化学习把求解过程看成连续交互：

- **状态**：当前 MIP、节点、搜索树等信息；
- **动作**：选一个变量、节点或割；
- **奖励**：例如求解时间减少、树变小、界得到改善；
- **策略**：从状态到动作的规则。

它不满足于“像老师”，而是尝试直接优化长期表现。但训练通常更困难，奖励设计和泛化也更复杂。

### 7.4 为什么使用图神经网络？

一个 MIP 可以自然表示为二分图：

```text
变量节点 x1 ───── 约束节点 1
变量节点 x2 ─┬─── 约束节点 1
             └─── 约束节点 2
变量节点 x3 ───── 约束节点 2
```

变量与约束相连，表示该变量出现在该约束中。节点和边还可以携带系数、上下界、当前 LP 值等特征。

图神经网络适合处理这种结构，因为：

- 不同实例可以有不同数量的变量和约束；
- 变量与约束之间的关系比简单表格更重要；
- 网络可以通过消息传递聚合邻域信息。

综述中的二分图、三分图和 GCN，主要就是在解决“怎样把 MIP 喂给神经网络”的问题。

## 8. 一个最关键的问题：用了机器学习，还能保证最优吗？

**不能一概而论，取决于机器学习替换了哪个环节，以及搜索是否仍保留完整证明。**

| 用法 | 是否通常保留精确性 | 原因 |
|---|---|---|
| 学习分支变量顺序，但仍完整搜索 | 可以保留 | 分支顺序影响速度，不改变所有整数解都被覆盖的事实 |
| 学习节点访问顺序，但不错误剪枝 | 可以保留 | 访问顺序改变，不必然丢掉解 |
| 只选择数学上已验证有效的割 | 可以保留 | 合法割不删除整数可行解 |
| 学习模型直接剪去“看起来没希望”的节点 | 可能失去保证 | 模型可能误删含最优解的区域 |
| 提前停止并返回当前最好解 | 不保证最优 | 搜索尚未完成，界还没有闭合 |
| LNS、可行性泵 | 通常是启发式 | 目标是快速找好解，而非完成最优性证明 |
| 神经网络直接预测变量取值 | 不自动保证可行或最优 | 预测可能违反约束，也未必最优 |

因此，“精确算法”和“使用机器学习”不是对立关系。**机器学习可以参与精确求解，但最终是否精确，要看算法有没有保留完整的可行性与最优性证明。**

## 9. 按什么顺序读这篇综述？

### 第一遍：只建立地图

建议顺序：

1. 摘要：知道论文讨论“机器学习 + MIP”；
2. 第 1 节：认识 MIP、LP 松弛、精确与启发式两条路线；
3. 第 2 节开头：理解 B&B 的搜索树、当前最好解和剪枝；
4. 第 3 节开头：理解为什么实际中需要启发式；
5. 第 4 节：看作者如何判断研究趋势。

第一遍可以跳过：所有参考文献、网络结构细节、ADMM、MDP、进化策略以及表格中的陌生缩写。

### 第二遍：抓住“决策点”

重点读：

- 第 2.1 节：选哪个变量分支；
- 第 2.2 节：选哪个节点搜索；
- 第 2.3 节：选哪些割；
- 第 3.1 节：选哪个邻域；
- 第 3.2 节：选下一个投影点；
- 第 3.3 节：选已有方法或辅助信息。

读每一段时只问三个问题：

1. 作者想让机器学习替代哪个选择？
2. 模型的输入和输出是什么？
3. 这样做影响速度、解质量，还是最优性保证？

### 第三遍：再读论文代表工作

可按以下顺序：

1. **Khalil et al., 2016**：学习分支，理解人工特征与监督学习；
2. **Gasse et al., 2019**：理解 MIP 二分图和 GCN；
3. **Gupta et al., 2020**：理解准确率与推理成本的权衡；
4. **Tang et al., 2020**：理解强化学习选割；
5. **Nair et al., 2021**：理解神经潜水、神经分支及组合系统；
6. **Sonnerat et al., 2021 / Wu et al., 2021**：理解学习型 LNS。

这篇综述发表于 2022 年，适合建立领域地图，但不应把其中的方法列表当成当前最新的全部进展。

## 10. 第一次动手：先会调用求解器，再考虑训练模型

下面的 Python 示例求解第 2 节的工厂问题，使用 SciPy 自带的 MILP 接口：

```python
import numpy as np
from scipy.optimize import Bounds, LinearConstraint, milp

# SciPy 做最小化，所以用负利润表示“最大化利润”
c = np.array([-3.0, -2.0])

# 2x + y <= 4，x + 2y <= 4
A = np.array([[2.0, 1.0], [1.0, 2.0]])
constraints = LinearConstraint(A, lb=-np.inf, ub=np.array([4.0, 4.0]))

result = milp(
    c=c,
    integrality=np.array([1, 1]),  # 两个变量都是整数
    bounds=Bounds(0, np.inf),       # x, y >= 0
    constraints=constraints,
)

print(result.message)
print("x, y =", result.x)
print("最大利润 =", -result.fun)
```

预期最优解是 $x=2,y=0$，最大利润为 6。

你可以做三个小实验：

1. 把 `integrality` 去掉，观察 LP 松弛给出的分数解；
2. 修改目标系数和设备上限，观察解如何变化；
3. 把变量改成只能取 0 或 1，理解“是否选择”的建模方式。

完成这些以后，再学习 Ecole、SCIP 或 Gasse 等人的代码，会容易很多。**不要一开始就从强化学习训练代码入手，否则很难分辨错误来自模型、求解器还是训练流程。**

## 11. 如果要做研究，怎样评价“更快、更好”？

只说“神经网络准确率很高”远远不够。分支预测准确率高，不代表最终求解更快。

至少要观察：

| 指标 | 它回答的问题 |
|---|---|
| 总求解时间 | 从头到尾到底快不快？ |
| 找到首个可行解的时间 | 多快能拿到可用方案？ |
| 达到指定解质量的时间 | 多快能达到实际可接受的水平？ |
| 最终目标值 | 返回方案有多好？ |
| 最优性 gap | 离完成最优性证明还有多远？ |
| 搜索树节点数 | 搜索规模是否减少？ |
| 模型推理时间 | 神经网络的额外开销是否抵消收益？ |
| 多实例、多随机种子表现 | 提升是否稳定，而非偶然？ |

还要特别检查：

- 训练实例和测试实例是否泄漏；
- 是否只在同分布、小实例上有效；
- 换到更大规模或不同结构后是否仍有效；
- 是否与强基线公平比较，而不只是与很弱的方法比较；
- 硬件、线程数、求解器版本和时间限制是否一致。

这个领域的核心难点通常不是“在一个数据集上把分类准确率做高”，而是**泛化、推理开销和端到端求解收益**。

## 12. 一条适合新手的学习路线

### 阶段 1：会描述问题

目标：能把简单现实问题写成变量、约束和目标。

练习：生产计划、任务分配、路径选择、装箱、排班。

暂时不用学机器学习。

### 阶段 2：会调用求解器

目标：用 Python 建模并求解小型 LP、IP、MILP；理解可行、不可行、无界、时间限制、当前最好解和 gap。

练习：修改参数、取消整数约束、比较求解时间和解。

### 阶段 3：理解传统算法

目标：能手算一个小型 B&B 搜索树，理解 LP 松弛、上下界、剪枝、强分支、割平面和基本启发式。

这一步是阅读综述的真正门槛。

### 阶段 4：补机器学习基础

目标：理解监督学习、训练/验证/测试划分、过拟合、 imitation learning、强化学习、MLP 和 GNN 的基本输入输出。

不需要一开始推导所有网络公式，先理解它们各自解决什么问题。

### 阶段 5：复现一个小实验

建议从“模仿分支规则”入手：

1. 收集一批小型 MIP 实例；
2. 运行专家分支规则并记录决策；
3. 训练一个简单模型；
4. 把模型接回求解流程；
5. 用端到端求解时间和树规模评价，而非只看预测准确率。

## 13. 新手最容易踩的十个误区

1. **“NP 难就是完全解不了。”**  
   错。很多实际实例可以快速求解；NP 难说的是一般意义下的最坏情况困难性。

2. **“NP 难就等于已经证明需要指数时间。”**  
   错。原文此处表述不严格，不能这样画等号。

3. **“求解器给出答案，就证明它最优。”**  
   错。达到时间限制时，它可能只返回当前最好解和 gap。

4. **“启发式算法找到的解一定很差。”**  
   错。它可能很快找到甚至最优解，只是通常没有完成最优性证明。

5. **“精确算法一定比启发式慢。”**  
   不一定。具体表现取决于实例结构、求解器和时间预算。

6. **“用了神经网络就不再需要传统求解器。”**  
   综述中的多数方法恰恰相反：神经网络嵌入求解器，辅助其中某些决策。

7. **“模仿专家就一定比专家好。”**  
   不一定。学生可能更便宜，也可能继承专家偏差；端到端效果必须实测。

8. **“预测变量分支配对率高，就说明求解更快。”**  
   错。错误发生在哪个节点、模型推理多久、后续树如何变化，都更重要。

9. **“割平面只是随便增加约束。”**  
   错。合法割不能删掉整数可行解，否则可能破坏正确性。

10. **“论文发表于 2022 年，所以表格就是当前全部方法。”**  
    错。它是入门地图，不是实时更新的排行榜。

## 15. 读完以后，你应当能复述的核心逻辑

MIP 的困难主要来自整数变量。求解器先通过 LP 松弛获得界，再通过分支把整数问题拆小，并利用界剪枝；割平面进一步收紧松弛。分支变量、节点和割的选择会显著影响速度，因此可以用机器学习从历史实例中学习这些决策。若时间有限，也可以用 LNS、可行性泵等启发式方法快速寻找好解，或让机器学习预测初始解、选择已有策略。机器学习的主要价值是降低搜索成本，但它不自动保证可行性或最优性；评价时必须看端到端求解时间、解质量、gap 和泛化能力，而不能只看神经网络指标。
